# สมาชิก Dashboard / Analytics

## สถานะ

Atlas Plus ใช้แผน `ATLAS_DASHBOARD` และตาราง `Subscription` จาก migration `20261108010000_add_subscriptions` ระบบนี้เปิดสิทธิ์ด้วยแอดมิน ยังไม่มี checkout, recurring billing หรือ webhook จากผู้ให้บริการชำระเงิน

## ตั้งค่า

1. ติดตั้ง dependencies และ generate Prisma client ตาม README
2. ตั้ง `DATABASE_URL` และ `DIRECT_DATABASE_URL` หากใช้การเชื่อมต่อแยกสำหรับ migrations
3. ใช้ `pnpm exec prisma migrate deploy` กับฐานข้อมูลที่ต้องการเปิดระบบ หลังตรวจสอบ migration ที่ยังไม่ได้ใช้
4. ตั้ง `ADMIN_BASIC_USER` และ `ADMIN_BASIC_PASSWORD` ให้ชัดเจนใน environment ของเซิร์ฟเวอร์
5. เข้าสู่ `/admin-login` ด้วยข้อมูลนั้น แล้วเปิด `/admin/subscriptions` จากเมนูผู้ดูแลหรือโปรไฟล์

หน้าจัดการสมาชิกต้องใช้บัญชี ADMIN จริง บัญชีทดลองไม่อ่านหรือแก้รายการสมาชิกจริง ทุกการเปลี่ยนสิทธิ์ตรวจบทบาทจากฐานข้อมูลและยืนยันรหัสผ่านแอดมินอีกครั้ง ฟีเจอร์นี้ไม่ใช้ค่าเริ่มต้นของรหัสผ่านในระบบล็อกอินเดิม

## เปิดและต่ออายุสิทธิ์

- ผู้ใช้ต้องสมัครบัญชีก่อน แอดมินกรอกอีเมลเดียวกับที่สมัครและเลือกวันสุดท้ายที่ใช้สิทธิ์ได้
- วันสิ้นสุดใช้เวลาไทย (Asia/Bangkok) เช่น เลือก 8 พฤศจิกายน 2026 จะใช้ได้จนก่อน 9 พฤศจิกายน 00:00 น. เวลาไทย โดยเก็บ boundary เป็น `2026-11-08T17:00:00Z`
- การบันทึกตั้งวันสิ้นสุดเป็นวันที่เลือก ไม่ได้บวกจำนวนวันเข้ากับสิทธิ์เดิม
- ใช้ provider `MANUAL` และ providerReference เป็น user ID เพื่อ upsert สิทธิ์เดิมเมื่อส่งซ้ำ ต่ออายุ หรือเปิดใหม่หลังยกเลิก
- ยกเลิกแล้วสิทธิ์ MANUAL สิ้นสุดทันที หากมี subscription อื่นที่ยังใช้ได้ ผู้ใช้ยังมีสิทธิ์ตามรายการนั้น
- สมาชิกดูสถานะและวันสิ้นสุดใน `/profile` ได้ เมื่อหมดอายุจะถูกปฏิเสธที่ `/dashboard` และ `/analytics` โดยไม่ต้องรอ cron เปลี่ยนสถานะฐานข้อมูล
- หากฐานข้อมูลขัดข้อง จะแสดงสถานะตรวจสอบไม่ได้และไม่อนุญาตเข้า dashboard

## ตรวจสอบ

รัน `pnpm test` และ `pnpm typecheck` จากนั้นทดสอบกับฐานข้อมูล development:

1. สมัครบัญชีสมาชิก เปิด `/dashboard` และตรวจว่าไปหน้าเลือกแผน
2. เข้าบัญชีแอดมิน เปิดสิทธิ์อีเมลนั้นจนถึงวันในอนาคต
3. เปิดสิทธิ์อีเมลเดิมอีกครั้งและตรวจว่ามี MANUAL row เดียว พร้อมวันสิ้นสุดใหม่
4. กลับเข้าบัญชีสมาชิก ตรวจสถานะในโปรไฟล์และเปิด Dashboard/Analytics
5. แอดมินยกเลิกสิทธิ์ แล้วตรวจว่าสมาชิกเข้า Dashboard/Analytics ไม่ได้
6. ลองรหัสผ่านแอดมินผิด อีเมลที่ยังไม่สมัคร และวันที่ผ่านมาแล้ว ต้องไม่บันทึกสิทธิ์
7. ตรวจข้อความไทย/อังกฤษและฟอร์มบนมือถือ

## งานถัดไปก่อนเก็บเงินจริง

ระบบยืนยันตัวตนเดิมยังเชื่อถือ cookie อีเมล และการสมัคร/เข้าสู่ระบบยังไม่ได้พิสูจน์ว่าเป็นเจ้าของอีเมล จึงยังไม่เหมาะสำหรับป้องกันข้อมูลส่วนตัวหรือสิทธิ์ที่มีการชำระเงินจริง แม้การเปลี่ยนสิทธิ์ในฟีเจอร์นี้จะต้องยืนยันรหัสผ่านแอดมินแล้วก็ตาม ต้องพัฒนาการยืนยันตัวตนและ session ที่ตรวจสอบความถูกต้องได้ก่อน พร้อมการจำกัดจำนวนครั้งที่ยืนยันรหัสผ่านและ audit log หากนำไปใช้งานจริง

หลังจากนั้นจึงเชื่อมผู้ให้บริการชำระเงิน ตรวจลายเซ็น webhook บันทึก event แบบ idempotent และกำหนดนโยบายยกเลิก/ต่ออายุสำหรับ subscription จากผู้ให้บริการนั้น
